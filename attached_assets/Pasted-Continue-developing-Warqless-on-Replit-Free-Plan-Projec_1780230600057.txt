==================================================

1. MAIN GOAL
   ==================================================

I want Warqless to clearly demonstrate these security principles:

1. No direct book download.
2. No public PDF/file URL.
3. Books open only inside the Warqless reader.
4. The account is permanently linked to one physical device.
5. This is NOT just one active session.
6. If the account is linked to Device A, it must not open on Device B even if Device A is logged out.
7. Changing the device requires a support/admin reset request.
8. Every book opening must pass a license/access check.
9. Reader must not open unpurchased or unborrowed books.
10. Watermark must appear inside the reader.
11. Screenshot/screen recording protection should be added where possible.
12. Any suspicious event should be logged and visible in Admin dashboard.
13. Every important student action should have a related admin preview/control.

==================================================
2. IMPORTANT CLARIFICATION — DEVICE BINDING
===========================================

Do NOT implement this as only “one active session at a time.”

I do NOT mean:

* Device A is logged in
* Device B tries to log in at the same time
* Device B is blocked only because Device A is currently active

That is not enough.

I want permanent device binding:

One account = one registered physical device.

Rules:

* First login from Device A registers Device A as the Primary Device.
* After that, the account can only open from Device A.
* If Device A logs out, Device B must still be blocked.
* If there is no active session on Device A, Device B must still be blocked.
* If Device B has the correct email and password, Device B must still be blocked.
* The app must not auto-replace the primary device.
* Device change must require an admin/support reset request.

Required blocked message:

Arabic:
هذا الحساب مرتبط بجهاز آخر. لا يمكن فتح الحساب إلا من جهاز واحد فقط.

English:
This account is linked to another device. It can only be opened from one device.

For this Replit MVP:

* Simulate permanent device binding using the current device service/local storage/shared mock state.
* Make the logic and labels very clear.
* Add code comments explaining that production must enforce this server-side.

For production later:

* Backend must be the source of truth.
* App only provides device identity.
* Backend decides if the device is allowed or blocked.

4. SECURITY EVENT SYSTEM
========================

Create a lightweight MVP Security Event system.

Use mock/shared/local data if needed.

Create events for:

1. device_registered
   When account is linked to first device.

2. device_verified
   When the same registered device successfully logs in.

3. device_blocked
   When another device tries to open the same account.

4. device_reset_requested
   When student requests device change.

5. device_reset_approved
   When admin approves reset request.

6. device_reset_rejected
   When admin rejects reset request.

7. reader_opened
   When a student opens a purchased/borrowed book.

8. reader_access_denied
   When a student tries to open a book without purchase/borrow.

9. license_check_failed
   When access/license check fails.

10. screenshot_attempt
    When screenshot/screen recording is blocked or detected, if possible.

11. suspicious_activity
    For repeated blocked attempts or repeated reader denials.

Security event fields:

* id
* type
* severity
* userId
* userName
* userEmail
* bookId optional
* bookTitle optional
* deviceId masked
* message
* metadata optional
* createdAt

Severity levels:

* low
* medium
* high
* critical
