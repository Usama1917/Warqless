You are a senior full-stack product architect, UI/UX designer, mobile app developer, backend engineer, and security-focused SaaS builder.

I want you to build a complete application from scratch called:

Warqless

Warqless is a digital platform for educational books, especially external school books and study books. The main goal is to replace the traditional printed book experience with a cheaper, smarter, protected, and interactive digital book experience.

The app should allow students to buy licensed digital books from publishing companies, read them inside the app only, write notes and highlights, borrow/lend books in a controlled way, and access interactive study features. The platform should also include an admin dashboard and publisher dashboard so book companies can upload, manage, sell, and track their digital books.

The brand idea:
Warqless = books without paper.
Main slogan:
“Your books. No paper.”
Arabic slogan:
“كتبك من غير ورق”

The product is mainly targeting students and educational book publishers in Egypt and the Arab world.

4. SECURE DIGITAL READER
==================================================

The digital reader is the most important part of the app.

The user must not receive an open downloadable PDF.

The reader should:
- Open books only inside the app
- Stream or securely load book pages
- Prevent direct file download
- Prevent copy/paste where possible
- Prevent printing
- Prevent screenshots where possible, especially on Android using FLAG_SECURE or equivalent
- Display visible or semi-visible watermark with user ID / phone / email / order ID
- Add hidden forensic watermark if technically possible
- Track reading session activity
- Detect suspicious behavior such as too many device changes or abnormal page capture patterns

Reader features:
- Page navigation
- Smooth page flipping
- Zoom in/out
- Search inside book if OCR/text layer exists
- Table of contents
- Go to page number
- Continue from last page
- Light/dark/sepia reading mode
- Font controls only if book is reflowable; otherwise PDF/image page view
- Bookmarks
- Highlights
- Text notes
- Handwritten pen annotations
- Eraser
- Different pen colors
- Different pen thickness
- Undo/redo
- Save annotations per user and per book
- Sync annotations to cloud
- Offline cache only if secure and license-limited

Important:
Basic note editing and erasing should be included for users who bought the book. Do not make basic erasing a paid feature because that would feel unfair. Instead, premium subscription features can include advanced tools such as cloud sync, export, AI summaries, flashcards, advanced pen layers, and study analytics.

5. DEVICE RESTRICTION AND LICENSE SYSTEM
==================================================

Each book purchase creates a digital license.

Rules:
- A user can read the book only from authorized devices.
- Default: allow one primary device.
- Optional: allow two devices if admin/publisher chooses.
- Do not allow the same account to read the same book on multiple devices at the same time.
- Device changes should be limited.
- User can request device reset through support.
- Admin can manually reset devices.
- Track device fingerprint, platform, app version, IP logs, and last active time.

Recommended license behavior:
- The app requires online verification before opening a book.
- Optional short offline grace period can be supported, such as 24–48 hours after last successful license check.
- After grace period, user must reconnect to verify license.
- If suspicious behavior is detected, temporarily lock the license and notify support/admin.

License states:
- Active
- Expired
- Suspended
- Refunded
- Borrowed out
- Borrowed in
- Pending verification

==================================================
6. BOOK LENDING / BORROWING FEATURE
==================================================

This is one of the unique features of Warqless.

The goal is to simulate lending a physical book:
If I lend my book to someone, I cannot use it while they have it.

Lending rules:
- Publisher can enable or disable lending per book.
- Publisher can define lending duration:
  - 3 days
  - 7 days
  - 14 days
  - Custom duration if allowed by admin
- Publisher can define maximum number of lends per purchased license.
- While the book is lent, the original owner cannot open the book.
- Borrower can read the book only inside the app.
- Borrower cannot re-lend the book.
- Borrower cannot download/export/copy/print the book.
- At the end of the lending period, access returns automatically to the owner.
- Owner can see current lending status.
- Borrower can return early.
- Lending can be free or paid depending on publisher/admin settings.

Lending flow:
1. Owner opens a purchased book.
2. Clicks “Lend this book”.
3. Enters borrower phone/email/user ID.
4. Chooses lending duration if multiple options are available.
5. App shows warning:
   “You will not be able to read this book during the lending period.”
6. Owner confirms.
7. Borrower receives notification/invite.
8. Borrower accepts.
9. License state changes:
   Owner: Borrowed out
   Borrower: Borrowed in
10. Access automatically returns after expiration.

Admin should be able to:
- View all lending transactions
- Disable lending globally
- Disable lending for specific books
- Investigate suspicious lending behavior
